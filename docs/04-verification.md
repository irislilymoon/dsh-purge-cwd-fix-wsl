# 04 · 验收

> 验收目标：确认“启动不再卡”“登录/余额按需保留”“回退成功”。
> 如果失败，按最后一节收集信息并回滚，不要反复改文件。

## 0. 前置确认

```bash
node -v
dsh --version
node scripts/diagnose.mjs
```

期望：

- Node 26.x；
- dsh `0.2.1-rc.2`；
- dsh-purge `1.1.71`；
- 6 个补丁 `applied`（desktop 可选）。

apply 之后：

```bash
node scripts/apply.mjs --dry-run
```

必须显示：

```text
Dry run: 0 file(s) would be patched; nothing written.
```

## 1. 重启

在正在运行 `dsh web` 的终端按 `Ctrl+C`，然后：

```bash
dsh web
```

记下新的 token URL。**不要**用 `pkill`/`kill` 杀进程；如果你有多个实例，
先确认端口 3080 上的是哪一个。

## 2. 启动时间

打开浏览器（建议新标签页/禁用缓存），从页面开始加载到**输入框出现**：

| 场景 | 期望 |
| --- | --- |
| 无 dsh-purge | 约 **2 秒** |
| 有 dsh-purge | 约 **4 秒** |

允许范围：**≤ 8 秒**。不应再出现“40–100 秒完全不可用”。

修复前同样的测量是 40–100 秒。

## 3. 启动阶段不应再有账号详情请求

打开 DevTools → Network，筛选 `account`：

- 页面启动、输入框出现之前，不应出现：
  - `/api/account/getProfile`
  - `/api/account/getBalance`
  - `/api/account/getUnnotifiedBonuses`
- 只有在你**打开账号菜单/设置页**之后，才应该出现这三类请求。

如果启动阶段仍有，说明 account 补丁未生效或页面用了旧缓存：
重启 dsh web，确认 `diagnose` 为 `applied`，再试。

## 4. 登录与账号菜单

1. 点击左下角/侧边栏“账号菜单”；
2. 期望：
   - 可以看到“退出登录”；
   - 菜单打开后触发 profile/余额/bonus 请求；
   - 资料/余额若返回，正常显示；若 30 秒后失败，见第 8 节。
3. 不需要退出登录；不要在这里测试退出，以免影响后续。

**登录状态是本地读取的**，即使详情查询失败，登录/provider 仍应工作。

## 5. 新建会话与历史

1. 点“新建会话”；
2. 期望立即进入输入框；
3. 打开侧边栏，历史会话列表应正常出现；
4. 点击一个历史会话，应正常打开。

修复前这些操作会全部无响应。

## 6. 回退

选一个**至少有一条用户消息**的会话（不要用空会话）：

1. 点输入框右侧的“回退”；
2. 选择“回退一次”；
3. 期望：
   - 按钮不显示“回退失败”；
   - 上一句用户消息被放回输入框；
   - 服务端 `/dsh-purge/rewind` 返回 `ok: true`，包含
     `sessionId` / `text` / `at`；
   - 会话仍停留在当前会话（不新开分支）。

“回退上一轮”用于带子代理的轮次：会把主会话和这一轮子代理一起回退。
如果你想验证，选一个明确带子代理的轮次；普通会话点“回退一次”即可。

失败时：

- 看浏览器按钮的 `title`（完整错误）；
- 看 dsh 终端是否有 `没有清掉之前发送的内容`；
- 按 [06-troubleshooting.md](06-troubleshooting.md) 处理。

## 7. dsh-purge 面板

1. 打开 dsh-purge 面板；
2. 期望：
   - 初始状态正常加载；
   - “检测更新”按钮可点；点它会发 `/dsh-purge/update`（手动触发）；
   - 页面加载时**不会**自动发 `/dsh-purge/update`；
   - rewind 仍按 1.2 秒轮询（Network 里可看到，正常且轻量）。
3. 不要为了验收去点“应用/还原/卸载”，除非你明确要修改插件补丁。

## 8. 账号余额查询仍可能失败（已知取舍）

如果在账号菜单打开后，`getBalance` / `getUnnotifiedBonuses` 仍然 30 秒超时：

- 这是 WSL 到 platform 的原有连接问题；
- 它**不再阻塞启动/新会话/历史/回退**；
- 主界面、登录、模型调用不受影响；
- 可以尝试：关闭菜单重开、稍后重试、换网络/DNS；
- 不要因为这一项回滚启动修复。

本仓库的目标是“启动不再被账号详情阻塞”，不是“修复 WSL 平台连接本身”。

## 9. 终端日志检查

启动后终端不应再出现启动阶段的：

```text
[deepseek-account] request failed { path: '/auth-api...', errorCode: 'no-response' }
```

注意：

- 打开账号菜单后出现一次余额失败是已知取舍；
- 不要贴 token/凭据；
- 模型 listing 的那行日志是正常的，可能仍出现。

## 10. 失败处理

如果启动仍 >15 秒，或出现新的启动错误：

1. 停止，不要继续改；
2. 收集：
   - `node scripts/diagnose.mjs --json`（不要包含凭据）；
   - 浏览器 Network 的慢请求/失败请求（URL、状态、耗时）；
   - dsh 终端最近 50 行（移除 token）；
3. 若确认由本仓库补丁导致：

```bash
node scripts/revert.mjs
```

然后重启 dsh web。
4. 把信息按 [AGENT_PROMPT.md](../AGENT_PROMPT.md) 的报告模板反馈。

## 11. 成功标准（全部满足）

- [ ] `diagnose` 6 项 `applied`；
- [ ] `apply --dry-run` 0 个待改；
- [ ] 重启后页面 **≤ 8 秒**可用；
- [ ] 启动阶段无 `/api/account/*` 详情请求；
- [ ] 账号菜单显示“退出登录”，打开后按需加载；
- [ ] 新会话/历史正常；
- [ ] “回退一次”成功，上一句回到输入框；
- [ ] “检测更新”手动可用；
- [ ] 没有破坏登录/模型调用。

第 8 节的余额超时是已知例外，不算启动修复失败。
